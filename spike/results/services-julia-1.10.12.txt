# Phase 0 -- context services (open item #12)
julia = 1.10.12

## Service (a): product-with-log-scale
   contract: (left, right) -> (distribution, logscale::Real)
   prod(N(0,1), N(1,2)) = NormalWeightedMeanPrecision{Float64}(xi=0.5, w=1.5)
   logscale             = -1.6349113442053942

   Called with no graph, no Rocket and no engine types in the signature. That is
   the whole of what `rules/mixture/switch.jl` reaches an engine for today.

## Service (a'): the switch rule wired through `ctx`
   Mixture(:switch) -> Categorical{Float64, Vector{Float64}}(support=Base.OneTo(2), p=[0.8909031788043871, 0.10909682119561288])
   the rule asked `service(ctx, :product)`; nothing engine-shaped crossed the
   boundary, and the service is swappable per call.

## FINDING: incoming annotations have no declared route
   incoming log scales: out=-1.5 inputs=(-0.2, -0.7) -> total -2.4

   `args` holds message DATA and `ann` is an output sink, so an annotation that
   ARRIVES with a message has nowhere to go. Recommend a parallel accessor keyed
   like `m`: `args.ann_in[:out]`. Declaration stays about data; annotations must
   not participate in dispatch, since they must not select the mathematics.

## Service (b): node function with captured parameters and fixed arguments
   contract: nodefunction(ctx, target) -> callable of the FREE arguments only
   f(x,y,z) = x + 2y + 3z, with x=10 and z=100 fixed
   f_fixed(1.0) = 312.0   (expected 312.0)
   f_fixed(2.0) = 314.0

   This is what a delta backward rule towards `in_k` needs: every other input
   pinned to its current value, one free argument left. The rule receives a
   CALLABLE, never a node type, so it needs no access to the graph.

## Contracts, as they should be written down in Phase 3
   product : (left, right)      -> (dist, logscale::Real)
   nodefn  : (ctx, target)      -> callable of the free arguments
   linalg  : (matrix)           -> a factorisation object (replaces global cholinv)
   rng     : ()                 -> an AbstractRNG owned by the caller
   Rules declare what they need (`ctx = (:product,)`), so a missing service is a
   named diagnostic rather than a MethodError deep inside a body.
